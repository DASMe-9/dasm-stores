# Spec: Rating Summary Bar in ProductReviews

## السياق والمبرر

Salla أطلقت في Twilight 2.14.490 (2026-07-08) دعماً لـ "multi-factor ratings + detailed review breakdowns" عبر مكوّني `salla-comments` و`salla-rating-modal`. يُعيد هذا التفصيل للمستخدم صورة أشمل عن جودة المنتج قبل الشراء.

المكوّن الحالي في dasm-stores (`ProductReviews`) يعرض تقييمات فردية نجمة-بنجمة فقط، بدون تجميع أو ملخص. ملخص التوزيع (كم مراجعة حصلت على 5 نجوم؟ كم على 3؟) هو أبسط تطبيق للنمط الصحيح: **لا يستلزم تغييرات API** — البيانات موجودة في `reviews[].rating` المُمرَّر حالياً.

**الأثر:** يرى المستخدم فوراً ثقل التقييمات قبل قراءة التفاصيل → يرفع الثقة ويسرع القرار.
**الجهد:** تعديل ملف واحد، بيانات موجودة، بدون endpoint جديد.

## الحالة الراهنة في dasm-stores

### الملفات المعنية

| الملف | الدور |
|-------|-------|
| `components/product/ProductReviews.tsx` | المكوّن الوحيد المعني — 44 سطراً |
| `lib/api-server.ts` (السطور 229-236) | تعريف `StoreReview` — الحقول: `id`, `rating`, `title`, `body`, `customer_name`, `created_at` |

### السلوك الحالي

1. إذا `reviews` فارغة: رسالة "لا توجد تقييمات بعد."
2. إذا توجد مراجعات: قائمة `<ul>` — كل عنصر: نجوم + اسم العميل + عنوان + نص.
3. لا يوجد متوسط مرئي، ولا توزيع، ولا تاريخ مراجعة.

**المشكلة البصرية:** في صفحة منتج لديه 15 مراجعة بمتوسط 4.7 نجوم، لا يرى المستخدم هذا الرقم حتى يقرأ كل مراجعة.

## التغيير المقترح

### الواجهة (TypeScript signature)

لا تغيير في الـ props — المكوّن يستقبل `reviews: StoreReview[] | undefined` كما هو.

```typescript
// داخل المكوّن — إضافة منطق تجميع فقط
function buildRatingSummary(reviews: StoreReview[]): {
  average: number;         // متوسط الكل (1 رقم عشري)
  total: number;           // عدد المراجعات
  distribution: number[];  // [عدد 1⭐, عدد 2⭐, عدد 3⭐, عدد 4⭐, عدد 5⭐]
}
```

### البنية البصرية المقترحة

```
┌─────────────────────────────────────────┐
│ التقييمات                                │
│                                         │
│  ⭐ 4.7     [5⭐ ████████████ 12]       │
│  من 15     [4⭐ ████         4]        │
│  مراجعة   [3⭐ ▌            1]        │
│            [2⭐              0]        │
│            [1⭐              0]        │
├─────────────────────────────────────────┤
│  ── مراجعة فردية ...                   │
└─────────────────────────────────────────┘
```

- المتوسط + العدد على اليمين (RTL)
- أشرطة نسبية على اليسار — عرض كل شريط = `(count / total) * 100%`
- لون الشريط: `var(--c-brand)` أو `var(--primary)`
- لا صورة، لا icon library جديدة

### Variants

| variant | الشرط | السلوك |
|---------|-------|---------|
| `summary-visible` | `reviews.length >= 1` | يُعرض block الملخص كاملاً |
| `no-reviews` | `reviews.length === 0` | رسالة "لا توجد تقييمات" — لا تغيير |

### سلوك States

| الحالة | التوقع |
|--------|--------|
| `reviews = undefined` | مكوّن يُعيد `null` كما اليوم (لا تغيير) |
| `reviews = []` | رسالة "لا توجد تقييمات" (لا تغيير) |
| `reviews.length === 1` | يُعرض الملخص بـ `total=1` + شريط واحد ممتلئ |
| جميع التقييمات 5 نجوم | الشريط الخامس ممتلئ 100%، باقي الأشرطة 0% |
| `rating` خارج نطاق 1-5 | `Math.max(1, Math.min(5, Math.round(r.rating)))` قبل التجميع |

## معايير القبول

- [ ] يظهر متوسط التقييم (رقم عشري واحد) ومجموع المراجعات فوق قائمة المراجعات
- [ ] تُعرض أشرطة التوزيع الخمسة (5⭐ → 1⭐) بعرض نسبي صحيح
- [ ] الشريط يستخدم `var(--c-brand)` أو `var(--primary)` (يتكيف مع ثيم المتجر)
- [ ] لا يتأثر عرض المراجعات الفردية الحالي
- [ ] `created_at` يُعرض بتنسيق محلي عربي بسيط (مثال: "منذ شهر") — optional لكن مرغوب
- [ ] الكود يعمل مع SSR (لا `window` أو client-only calls في منطق التجميع)
- [ ] لا يُكسر عرض صفحة المنتج في حال `reviews` يحتوي على entries بـ `rating = 0` أو null

## مخاطر التغيير

| المخاطرة | الاحتمال | التخفيف |
|---------|---------|---------|
| المتوسط يُحسب بشكل خاطئ عند `rating` فارغة | منخفض | تصفية `r.rating > 0` قبل التجميع |
| الأشرطة تتمدد خارج container بـ RTL | متوسط | استخدام `dir="ltr"` على container الأشرطة فقط، وتسمية 5⭐ → 1⭐ بـ RTL خارجها |
| CLS (Cumulative Layout Shift) | منخفض | block الملخص ذو ارتفاع ثابت (fixed height div) |

## ملاحظة للمستقبل (ليست جزءاً من هذا الـ spec)

حين يدعم backend حقولاً إضافية لـ `StoreReview` مثل `images[]` أو sub-ratings (`rating_quality`, `rating_shipping`, `rating_accuracy`)، يتوسع هذا المكوّن بسهولة:
- `images[]` → إضافة thumbnail row تحت كل مراجعة
- Sub-ratings → استبدال شريط التوزيع الإجمالي بـ 3 أشرطة مستقلة

كلا التوسعَين لا يُغيِّران الـ props interface الحالية.
